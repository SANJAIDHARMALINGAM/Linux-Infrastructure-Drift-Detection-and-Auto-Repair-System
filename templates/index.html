Project Architecture & Scope

Linux Infrastructure Drift Detection & Auto Repair System

This project provides an automated configuration compliance monitoring and remediation workflow. It establishes an approved baseline reference, detects unintentional or unauthorized drift in monitored settings, enables controlled simulation of configuration changes, safely repairs drifted settings back to baseline values, and maintains a timestamped audit trail.

Test Environment Operational Scope
This prototype operates strictly on designated JSON configuration files (baseline.json and current_config.json). It is an educational prototype and does not directly alter live Linux OS system configurations (such as /etc/ssh/sshd_config, ufw firewall rules, or live system file permissions).

Unified System Architecture

Both the interactive terminal CLI (drift_detector.py) and this Flask web dashboard share the exact same underlying service module (core/drift_service.py). Neither transport layer duplicates comparison or repair algorithms.

Supported REST API Endpoints

  • GET /api/health — Service health and status check
  • GET /api/dashboard — Real-time system metrics, compliance status, and drift count
  • GET /api/configuration — Baseline vs current configuration comparison
  • GET /api/drift — Active drift issues calculation
  • POST /api/drift/detect — Trigger drift scan and generate report
  • POST /api/drift/simulate — Safely simulate drift in test configuration
  • POST /api/repair — Auto-repair with mandatory pre-backup and verification
  • GET /api/logs — Audit trail records
  • GET /api/reports — Historical JSON reports
  • GET /api/backups — List of saved backups
  • POST /api/backups/restore — Verified restore from backup
